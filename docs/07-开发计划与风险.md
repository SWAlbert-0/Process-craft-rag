# 开发计划与风险

## 1. 实施原则

- 先打通最小端到端链路，再优化检索质量和界面。
- 优先使用真实 PDF 和固定测试题，避免只用演示文本调优。
- 每个里程碑都有可运行产物和验证证据。
- 核心模块通过接口解耦，模型替换不改业务流程。
- 不把“API 能调用”视为里程碑完成，必须覆盖引用、失败和评估。

## 2. 里程碑

### M0：启动与基线确认

**任务**

- 确认样例文档、指令模板、模型服务商和部署资源。
- 初始化前后端、依赖锁定、代码规范、配置示例和 Docker Compose。
- 建立文档状态、索引版本和任务模型。
- 准备测试题集模板及评估表。

**交付物**：可启动的空系统、数据库迁移、配置说明、样例数据清单、基线决策记录。

**完成标准**：新环境按说明可启动；配置无硬编码密钥；核心数据表可迁移。

### M1：文档解析与索引

**任务**

- PDF 上传、内容去重、文件安全校验。
- 按页解析、清洗、分块和元数据保存。
- 嵌入生成、Qdrant 暂存集合、BM25 构建。
- 任务恢复、失败重试、版本发布、重建与删除。
- 文档管理基础页面。

**完成标准**：多份 PDF 可完成入库；两路索引块 ID 一致；失败可重试；重建和删除不污染活动版本。

### M2：混合检索与生成

**任务**

- 稠密和稀疏并行召回、RRF 融合、重排序。
- 上下文预算、提示词、LLM API、输出结构校验。
- 普通问答与加工指令两种模式。
- 引用白名单、快照、证据不足策略。
- 检索诊断日志与基础单测/集成测试。

**完成标准**：可查看四阶段候选结果；生成引用均能回到实际块；无答案时不编造完整指令。

### M3：会话与产品闭环

**任务**

- 登录、角色和会话归属。
- 新建/管理会话、历史消息、多轮查询改写。
- SSE 流式输出、失败重试、幂等提交。
- 引用抽屉、PDF 页定位、空状态和异常交互。
- 文档筛选与管理员工具完善。

**完成标准**：用户可独立完成完整流程；追问、断连、删除文档和越权场景符合约定。

### M4：评估与优化

**任务**

- 冻结多文档测试集，完成相关性标注。
- 实现评估运行、评分录入与导出。
- 执行 A/B/C/D 检索对比和人工评分。
- 调整分块、top-k、阈值、上下文及提示词。
- 完成异常、性能、安全和恢复测试。

**完成标准**：形成可复现评估报告；严重失败有处置；所有 P0 验收项有证据。

### M5：交付

**任务**

- 完善安装、配置、使用、备份恢复和限制说明。
- 准备不含敏感信息的演示数据与截图。
- 清理密钥、临时文件、调试代码和过期文档。
- 发布版本并记录已知问题。

**完成标准**：干净环境可部署，演示路径稳定，仓库与交付文档一致。

## 3. 工作分解

| 工作流 | 主要任务 | 依赖 |
| --- | --- | --- |
| 前端 | 登录、会话、引用、文档管理、评估页面 | API 约定 |
| 后端基础 | 配置、数据库、认证、文件与任务、错误规范 | M0 |
| RAG | 解析分块、嵌入、BM25、融合、重排序、生成 | 模型与文档 |
| 质量 | 单元/集成/E2E、测试集、人工评估、性能安全 | 各阶段产物 |
| 运维 | Compose、日志、备份、监控、部署文档 | 基础架构 |

## 4. 开发顺序与并行

1. 数据与接口约定先冻结首版，前端可使用固定 mock 并行开发。
2. 文档链路完成前，算法可用小型页文本样本开发检索单元，但联调必须使用真实索引。
3. 测试题和页级标注在 M1 同步准备，不能等系统完成后才选择有利样本。
4. 人工评估在 M2 开始预跑，M4 冻结结果，避免最后才发现检索或引用设计问题。

## 5. 风险清单

| 风险 | 影响 | 早期信号 | 应对 |
| --- | --- | --- | --- |
| PDF 扫描件或复杂表格导致解析差 | 检索知识缺失 | 页文本为空、参数错行 | 预检并明确限制；评估 OCR/表格扩展必要性 |
| 中文术语/型号检索差 | 关键资料未召回 | 精确查询失败 | BM25 保留规则、自定义词典、检查分词 |
| 分块破坏工序上下文 | 答案片面或引用错位 | 表头与参数分离 | 结构感知分块、相邻块合并、页级评估 |
| 向量模型不适合中文工艺语料 | 语义召回差 | Recall@k 低 | 用固定集比较模型，不凭通用榜单直接决定 |
| 重排序阈值误杀 | 有答案却拒答 | 候选相关但被过滤 | 校准阈值，保留诊断，按题型验证 |
| 大模型编造参数或引用 | 生产安全风险 | 无来源数值、非法编号 | 强约束、结构校验、白名单、拒答与人工审核 |
| 多轮历史污染检索 | 回答错对象 | 换话题仍检索旧实体 | 独立问题改写、限制历史、新会话隔离测试 |
| 索引状态不一致 | 删除后仍命中或版本混用 | 两路结果来自不同版本 | 暂存构建、活动版本指针、一致性检查 |
| SQLite 并发限制 | 写入失败或任务卡死 | 数据库锁定 | 单 worker、短事务、WAL；扩展时迁移 PostgreSQL |
| 模型 API 不稳定或成本高 | 响应失败、成本超预算 | 超时、限流、token 增长 | 超时重试、上下文预算、用量统计和告警 |
| 文档含提示注入 | 指令被覆盖或泄露 | 回答泄露系统提示 | 上下文与指令隔离、输出检查、密钥不进入提示 |
| 评估样本过少或标注偏差 | 指标失真 | 只测简单事实题 | 多文档多题型、困难题、双人复核关键样本 |
| 涉密资料外发 | 合规风险 | 使用外部模型处理敏感文档 | 数据分级、脱敏、内网模型或审批后使用 |

## 6. 质量完成定义（Definition of Done）

一个功能只有同时满足以下条件才算完成：

- 代码通过项目规定的格式检查、静态检查和测试。
- 正常路径及约定异常路径均验证。
- 权限、日志、配置和错误响应符合文档。
- 数据库变更提供迁移，索引变更说明版本与重建方式。
- API 或业务规则变化已同步文档。
- 无硬编码密钥、绝对本机路径或未经确认的依赖。
- 用户可观察到明确结果，不仅后台打印成功日志。
