# 需求分析

## 1. 背景与问题

企业已有工艺规程、作业指导书、材料与设备说明等资料多以 PDF 保存。通用大模型虽然能生成文字，但无法可靠掌握企业内部知识，也难以说明答案来源。项目需要建立一条可验证的知识检索与生成链路，使模型优先依据企业文档作答，并将结论追溯到具体文件和页码。

## 2. 项目目标

- 将多份 PDF 工艺资料转化为可检索、可管理的知识库。
- 综合语义相似度和关键词匹配，提高工艺术语、型号、参数等内容的召回能力。
- 通过重排序筛选真正相关的上下文，减少无关内容进入提示词。
- 根据用户零件加工问题生成结构化加工指令草案，并提供引用。
- 支持连续追问，同时避免历史对话污染当前检索。
- 建立可复现的人工评估方法，验证系统在多文档上的效果。

## 3. 用户角色

| 角色 | 核心诉求 | 主要操作 |
| --- | --- | --- |
| 工艺人员 | 快速获得有依据的加工建议 | 提问、追问、查看引用、导出或复制结果 |
| 知识库管理员 | 保证资料正确入库且可检索 | 上传、重建索引、查看失败原因、删除文档 |
| 评估人员 | 判断回答质量和检索效果 | 执行测试题、评分、记录问题 |
| 系统管理员 | 保证服务可用、配置安全 | 配置模型、查看日志、备份与恢复 |

MVP 可只实现“普通用户”和“管理员”两类权限，工艺人员与评估人员归入普通用户，知识库与系统管理归入管理员。

## 4. 范围

### 4.1 本期范围

1. PDF 上传、文本解析、页码保留、分块、向量化和索引管理。
2. 单知识库内的文档列表、处理状态、失败原因和删除。
3. 稠密召回、BM25 稀疏召回、结果融合及重排序。
4. 基于检索上下文的普通问答和零件加工指令草案生成。
5. 多轮对话、会话历史、检索问题改写。
6. 文档名、页码、原文片段构成的引用及原文定位。
7. 多文档测试集、人工评分和结果汇总。
8. 基础登录与管理员权限、服务配置、日志和异常提示。

### 4.2 非本期范围

- 自动生成可直接执行的 G 代码、控制机床或与 MES/ERP/CAPP 实时集成。
- 复杂 CAD 图纸理解、三维模型解析和几何特征自动识别。
- 无 OCR 条件下对纯扫描 PDF 的完整识别；OCR 可作为确认的扩展项。
- 企业级多租户、复杂组织架构、细粒度文档 ACL。
- 对模型进行预训练或微调。
- 保证生成结果无需人工审核即可用于生产。

## 5. 功能需求

### 5.1 文档管理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-DOC-01 | 管理员可上传 PDF，系统校验扩展名、MIME、大小和重复内容 | P0 |
| FR-DOC-02 | 系统异步展示待处理、解析中、索引中、已完成、失败状态 | P0 |
| FR-DOC-03 | 解析结果保留文档、页码和原始文本的映射 | P0 |
| FR-DOC-04 | 已完成文档可重建索引；失败任务可重试 | P0 |
| FR-DOC-05 | 删除文档时同步清理文件、元数据、向量及稀疏索引，或明确标记不可用并完成异步清理 | P0 |
| FR-DOC-06 | 用户可查看文档基本信息和分块数量 | P1 |

### 5.2 检索与生成

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-RAG-01 | 每个问题分别执行稠密和稀疏召回，且结果可分别统计 | P0 |
| FR-RAG-02 | 混合召回采用统一融合策略，参数可配置 | P0 |
| FR-RAG-03 | 重排序仅对融合后的候选集执行，并保留排序依据 | P0 |
| FR-RAG-04 | 生成提示词只使用过滤后的高相关上下文，并受上下文长度限制 | P0 |
| FR-RAG-05 | 回答中的事实性结论应带引用，引用至少含文档名和页码 | P0 |
| FR-RAG-06 | 证据不足时明确说明“不足以确定”，不得编造参数或来源 | P0 |
| FR-RAG-07 | 加工指令以固定结构输出，包含适用对象、准备事项、步骤、关键参数、质量与安全注意事项 | P0 |
| FR-RAG-08 | 支持限定检索文档范围，默认检索全部已完成文档 | P1 |

### 5.3 会话与引用

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-CHAT-01 | 用户可新建会话、发送问题、连续追问和查看历史 | P0 |
| FR-CHAT-02 | 系统结合近期历史生成独立检索问题，但原始问题仍保留 | P0 |
| FR-CHAT-03 | 新会话不继承其他会话上下文或文档筛选条件 | P0 |
| FR-CHAT-04 | 每条助手消息保存所使用的引用快照，历史消息可复查来源 | P0 |
| FR-CHAT-05 | 用户点击引用可查看对应文档、页码和命中片段 | P0 |
| FR-CHAT-06 | 支持流式输出；连接中断不重复创建用户消息 | P1 |

### 5.4 管理与评估

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-ADM-01 | 非管理员不能上传、重建或删除文档 | P0 |
| FR-EVAL-01 | 支持以固定问题、固定知识库版本和固定配置执行评估 | P0 |
| FR-EVAL-02 | 保存回答、检索结果、引用和人工评分，支持导出 | P0 |
| FR-EVAL-03 | 汇总正确性、完整性、引用质量、拒答合理性和检索指标 | P0 |

## 6. 非功能需求

以下为首版建议目标，测试环境确定后基线化。

| 类别 | 建议目标 |
| --- | --- |
| 性能 | 100 页以内文本型 PDF 可正常入库；非生成阶段检索 P95 不高于 3 秒；生成首字时间单独统计 |
| 容量 | MVP 支持不少于 100 份文档、10 万个文本块；超出时需重新评估 BM25 与数据库方案 |
| 可用性 | 单个文档失败不影响其他文档；服务重启后可恢复未完成任务 |
| 可观测性 | 记录请求 ID、任务 ID、各检索阶段耗时、候选数、模型错误；禁止记录 API 密钥 |
| 可维护性 | 解析器、嵌入模型、重排序器和大模型通过接口隔离，可替换实现 |
| 可复现性 | 回答保存模型名称和关键检索参数；索引关联嵌入模型版本 |
| 安全 | 文件类型与大小限制、身份认证、接口鉴权、路径防护、密钥环境变量配置 |
| 易用性 | 上传和生成均有明确状态；失败展示可理解的提示，不向前端暴露堆栈 |
| 兼容性 | 支持当前主流 Chrome/Edge；服务端优先保证 Windows 开发与 Linux 容器部署 |

## 7. 核心业务规则

1. 仅 `ready` 文档参与检索；失败、删除中和处理中的文档不可见。
2. 文档内容以 SHA-256 去重；同名不同内容视为不同文档。
3. 索引与嵌入模型版本绑定；模型变化必须全量或按文档重建，禁止混用不同维度向量。
4. 引用必须来自本次实际注入模型的上下文，不能仅依据生成文本中的编号临时拼凑。
5. 原始 PDF、页文本和分块 ID 是溯源基础，删除后历史引用保留快照但标记原文不可用。
6. 多轮历史用于理解问题，不直接视为企业知识证据。
7. 系统输出统一标注“AI 辅助生成，需由工艺人员审核”。

## 8. 约束与假设

- 默认 PDF 包含可提取文本，中文编码可正常解析。
- 大模型 API 可通过服务端访问；浏览器不直接接触模型密钥。
- 嵌入、重排序模型可下载或已有内网服务。
- 首版并发较低，可使用 SQLite；多实例部署前必须迁移至 PostgreSQL 并重新设计任务锁。
- 工艺指令具体模板尚未提供，首版模板属于产品默认值，需领域人员评审。

## 9. 验收条件

- 选题中的七项需求基线均有可运行功能和对应测试证据。
- 使用至少 3 份内容不同的 PDF 完成端到端演示：上传、索引、提问、追问、生成、引用查看。
- 能展示稠密、稀疏、融合与重排序各阶段结果，证明混合链路真实生效。
- 对无答案问题能明确拒答，不生成虚假引用。
- 按评估方案形成多文档人工评估记录和汇总结果。
- 所有 P0 异常路径有明确反馈，不出现任务永久无状态或文档删除后仍被检索。
