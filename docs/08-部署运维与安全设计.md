# 部署运维与安全设计

## 1. 环境划分

- **开发环境**：本机服务或 Docker Compose，使用独立测试数据和模型配额。
- **评估环境**：固定文档、索引和模型配置，避免评估期间自动更新。
- **生产/演示环境**：仅使用经批准的数据和密钥，启用 HTTPS、备份和访问控制。

不同环境使用不同数据库、存储目录、Qdrant collection 前缀和模型密钥，禁止共用数据目录。

## 2. 部署拓扑

MVP 使用 Docker Compose：

- `frontend`：构建后的静态资源，由 Nginx 或等价服务提供。
- `api`：FastAPI，单实例。
- `worker`：与 API 共用代码镜像，单实例处理持久任务。
- `qdrant`：开源向量数据库，挂载持久卷。
- SQLite、BM25 和 PDF 使用受控持久卷；API 与 worker 只共享必要的数据卷。

前端反向代理 `/api` 到后端，生产环境不直接暴露 Qdrant 和 SQLite。所有内部服务使用最小网络权限。

## 3. 配置与密钥

配置分为非敏感默认值和环境密钥。仓库只提交 `.env.example` 类模板，真实 `.env` 必须忽略且不得上传。

必需配置包括：

- 会话签名/认证配置和初始管理员的安全初始化方式。
- LLM Base URL、API Key、模型名、超时和重试。
- 嵌入及重排序模型位置或远程服务配置。
- Qdrant 地址和数据目录。
- 上传大小、允许来源、日志级别和检索参数。

要求：

- 不在前端环境变量中放模型密钥。
- 不在日志、异常、评估导出或 Git 中记录密钥。
- 密钥轮换后验证服务并撤销旧密钥。
- 第三方模型调用前确认文档数据外发合规性。

## 4. 数据目录与持久化

逻辑目录建议：

```text
data/
  db/                 # SQLite
  documents/          # 原始 PDF，以随机存储键命名
  parsed/             # 页文本与解析中间结果
  indexes/bm25/       # 版本化 BM25 索引
  evaluation/         # 评估导出（按权限控制）
  tmp/                # 可清理临时文件
backups/              # 独立备份位置
logs/                 # 可选文件日志
```

Qdrant 使用自身持久卷。应用不通过用户文件名拼接物理路径。

## 5. 日志与可观测性

### 5.1 结构化日志

每条请求包含 `request_id`；文档任务包含 `task_id`、`document_id`、`index_version_id`。核心事件：

- 登录失败、管理员操作和文档删除。
- 上传、解析、分块、嵌入、索引发布各阶段。
- 查询改写、两路召回、融合、重排序、生成与输出校验。
- 上游超时、重试、限流及最终失败。

### 5.2 指标

- API 请求数、错误率、P50/P95 延迟。
- 文档任务成功/失败数、队列等待时间、各阶段耗时。
- 检索候选数、空召回率、证据不足率、降级率。
- LLM 首字时间、总耗时、输入/输出 token、估算费用。
- Qdrant 和磁盘可用空间、数据目录增长。

### 5.3 隐私

默认不记录完整问题、文档正文和模型提示词；诊断需要时应在受控环境采样并脱敏。引用与评估数据按业务数据保护，不写入普通调试日志。

## 6. 备份与恢复

### 6.1 备份对象

- SQLite 一致性备份，而非在写入时直接复制数据库文件。
- 原始 PDF 和必要解析数据。
- Qdrant 快照及 BM25 索引；索引可重建时仍需保存版本配置。
- 非敏感配置、模型版本、数据库迁移版本和评估记录。

### 6.2 恢复验证

恢复后检查文档与活动版本一致性、Qdrant 点数、BM25 块数及抽样引用。执行固定问题进行检索冒烟测试。备份只有经过恢复演练才算有效。

备份频率和保留期由数据重要程度决定；首版至少支持手动全量备份和恢复说明。

## 7. 安全设计

### 7.1 身份与权限

- 密码哈希使用成熟算法，不明文保存。
- 登录限流，统一登录失败提示。
- 会话 Cookie 设置 HttpOnly、SameSite；HTTPS 下设置 Secure。
- 所有管理接口服务端鉴权，不能依赖前端隐藏按钮。
- 会话和消息按用户隔离；文档访问按角色控制。

### 7.2 文件与输入

- 限制扩展名、真实 MIME、大小、页数和处理时长。
- 随机存储键，拒绝路径穿越；上传目录不可执行。
- PDF 解析器保持更新，异常文件在受限 worker 中处理。
- 输出到页面时防 XSS，富文本采用白名单或安全 Markdown 渲染。
- 导出的 CSV 防止公式注入，下载文件名正确编码。

### 7.3 RAG 特有安全

- 检索文档是数据，不是系统指令；提示词明确隔离。
- 不把密钥、完整系统提示或内部存储路径放入模型上下文。
- 对外部链接、文档中的操作指令和“忽略之前要求”等内容保持不可信处理。
- 引用只能来自服务端白名单，降低伪造来源。
- 工艺输出显示人工审核提示，禁止直接连接生产控制设备。

### 7.4 网络与依赖

- 仅暴露 Web/API 端口；Qdrant 不设置匿名公网访问。
- 对外模型请求使用 TLS、超时和有界重试。
- 锁定依赖并执行漏洞扫描；模型文件从可信来源获取并校验。
- 跨域来源采用明确白名单，不使用带凭据的通配符 CORS。

## 8. 可用性与恢复

- API 提供存活与就绪检查；就绪检查应验证关键元数据和 Qdrant 连接，但不泄露细节。
- worker 任务带租约和最大尝试次数；死信任务需管理员查看。
- 启动时清理过期临时文件，恢复可恢复任务，隔离不一致索引。
- LLM 或重排序不可用时不影响已有历史与文档管理。
- 磁盘空间不足时停止新上传，避免损坏现有数据。

## 9. 成本控制

- 查询改写仅在需要时调用，或使用可验证的轻量策略。
- 对文档分块批量嵌入，避免重复索引相同内容。
- 限制历史轮数、上下文块数和最大输出 token。
- 缓存模型实例和连接；是否缓存生成答案需谨慎，避免跨用户知识泄露。
- 评估按文档、配置和题目统计 token 与费用，异常增长告警。

## 10. 上线检查清单

- [ ] 真实密钥未进入 Git、镜像、前端包和日志。
- [ ] 数据库、Qdrant、PDF 与索引目录均已持久化。
- [ ] 管理员初始账户已安全设置，默认口令不存在。
- [ ] HTTPS、CORS、Cookie 和接口鉴权验证通过。
- [ ] 上传限制、越权、恶意文件名和提示注入测试通过。
- [ ] 备份与恢复至少演练一次。
- [ ] 服务重启后任务和索引状态正确。
- [ ] 多文档人工评估达到团队确认标准。
- [ ] 已知限制和人工审核责任在界面及交付说明中可见。
- [ ] 模型用量、错误率、磁盘空间和失败任务可观测。
