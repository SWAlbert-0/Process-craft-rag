# 测试与评估方案

## 1. 目的

验证系统不仅“能生成”，而且检索链路有效、答案有依据、多文档结果可复查。测试分为软件正确性、检索效果、生成质量和安全异常四类；人工评估不能由自动测试替代。

## 2. 测试环境与数据

### 2.1 文档集

至少准备 3 份内容不同的文本型 PDF，建议覆盖：

- 典型零件加工工艺或作业指导书。
- 刀具、切削参数、设备或材料资料。
- 检验、质量或安全规范。

另准备异常样本：加密 PDF、损坏 PDF、纯扫描 PDF、含复杂表格 PDF、无正文 PDF、同名不同内容文件。测试资料必须获得使用授权，不在公开仓库提交涉密文档。

### 2.2 测试题集

首版建议不少于 30 题，且覆盖所有正常文档；正式规模由评估人员确认。题型包括：

- 单文档事实抽取：术语、步骤、参数、检验要求。
- 同文档跨页综合：需要连接工序与参数。
- 多文档综合：需综合不同来源。
- 精确型号/数值查询：验证 BM25 的补充价值。
- 语义改写查询：验证稠密召回。
- 多轮指代与省略：验证改写和会话边界。
- 无答案问题：验证拒答。
- 冲突或过期资料：验证来源呈现和谨慎表达。

每题保存：ID、问题、题型、关联文档、期望答案要点、必须引用页、可接受变体、是否应拒答、难度、标注人。检索标注还需保存相关块/页列表。

## 3. 软件测试

### 3.1 单元测试

- PDF 清洗、页码映射、分块边界和确定性 ID。
- 中文分词与型号/单位保留。
- RRF 手工样例、去重、稳定排序。
- 上下文 token 预算和重复块处理。
- 多轮问题改写的输入构造。
- 提示词引用白名单、JSON 结构校验、非法引用处理。
- 文档与任务状态机、权限和输入校验。

### 3.2 集成测试

- 上传至 `ready` 的完整索引链路，核对页数、块数及两路索引一致性。
- 同一文件重复上传、失败重试、重建版本切换和删除清理。
- 稠密与稀疏结果均进入融合，重排序真实改变或确认候选顺序。
- 提问、历史保存、追问、文档过滤和引用快照。
- 向量库、模型 API 不可用及超时错误。
- 用户不能访问他人会话，普通用户不能管理文档。

### 3.3 端到端测试

按用户视角执行：

1. 管理员登录并上传多份 PDF。
2. 等待索引成功，检查文档列表和分块。
3. 用户创建会话，分别执行知识问答和加工指令。
4. 检查答案结构、引用页码和原文片段。
5. 连续追问并确认检索问题包含必要实体。
6. 删除一个文档，确认其不再参与新检索且历史引用仍可读。
7. 运行评估、录入评分并导出。

### 3.4 非功能测试

- 不同页数 PDF 的处理耗时、内存与失败恢复。
- 检索 P50/P95、生成首字时间、完整响应时间分别统计。
- 并发提问、重复提交和 SSE 断连。
- 服务重启后的任务恢复、索引一致性与数据持久性。
- 大文件、路径穿越文件名、恶意提示文档和越权请求。

## 4. 检索评估

有相关块/页标注时，分别评估稠密、稀疏、融合及重排序：

| 指标 | 含义 |
| --- | --- |
| Recall@k | 相关结果是否进入前 k，重点看重排序前的候选覆盖 |
| MRR | 首个相关结果的倒数排名均值 |
| nDCG@k | 多级相关性标注下的排序质量 |
| Hit Rate | 至少命中一个相关结果的问题比例 |

同时记录：

- 仅被稠密找到、仅被稀疏找到、两路共同找到的问题数。
- 重排序后相关块排名上升/下降情况。
- 空召回、低分过滤和上下文截断样本。
- 各阶段耗时。

没有相关块标注时，不得伪造检索指标，可先基于人工核对页级相关性，再补充标注。

## 5. 人工生成评估

### 5.1 评分维度

采用 0–2 分，评分只针对当前问题，不因文字流畅而掩盖事实错误。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 正确性 | 核心结论错误、存在危险或无依据参数 | 部分正确但有明显遗漏/错误 | 核心结论与依据一致，无实质错误 |
| 完整性 | 未回答主要问题 | 覆盖部分要点 | 覆盖期望要点且缺失项说明合理 |
| 引用正确性 | 引用不存在、不支持结论或无法核查 | 部分引用有效但遗漏关键依据 | 关键结论均有真实、对应来源 |
| 相关性/表达 | 答非所问或不可理解 | 基本相关但冗余或结构混乱 | 清晰、简洁、结构符合模式 |
| 多轮一致性（适用题） | 指代理解错误或串用其他会话 | 部分理解但需补充 | 正确理解上下文且未引入无关历史 |

### 5.2 拒答题目单独规则

- 应拒答且明确说明证据不足、未编造答案：正确性 2 分。
- 给出部分有依据内容并指出缺失，也算合理行为。
- 应拒答但生成确定答案或无依据参数：正确性 0 分。
- 有充分答案却无故拒答：完整性和正确性不得满分。

### 5.3 加工指令额外检查

- 步骤顺序是否与依据一致。
- 材料、设备、刀具、参数和公差是否来自输入或引用。
- 缺失信息是否标为待确认。
- 质量与安全事项是否有依据且未夸大。
- 是否始终保留人工审核提示。

出现编造关键工艺参数时，该样本判为严重失败，即使其余文字正确也不能计为有效回答。

## 6. 评估流程

1. 冻结文档内容哈希、活动索引版本、模型名称和检索配置。
2. 冻结测试题集版本，确保模型调参前后使用同一数据。
3. 批量运行并保存原始输出，不允许评分前手工修改回答。
4. 至少由 1 名熟悉工艺资料的评估人员独立评分；关键项目建议双人评分。
5. 评分人查看问题、期望要点、回答和引用原文；对严重失败记录原因。
6. 双人评分分歧先讨论并记录仲裁结果；可报告一致性。
7. 自动汇总均值、比例和置信区间（样本足够时），按题型与文档拆分。
8. 形成失败分类和改进建议，更新配置后创建新运行，不覆盖旧结果。

## 7. 汇总指标

- 正确性平均得分、完整性平均得分、引用正确性平均得分。
- 有效回答率：正确性与引用正确性均为 2 且未发生严重失败的题目占比。
- 引用可核查率：抽查引用中真实存在且定位正确的比例。
- 引用支持率：被检查的事实结论中，引用确实支持该结论的比例。
- 正确拒答率：无答案题中合理拒答的比例。
- 无依据参数率：出现无依据关键参数的回答占比。
- 检索指标、耗时与失败率单独报告，不与人工分数混为一个“准确率”。

建议首版目标：有效回答率不低于 80%、引用可核查率 100%、无依据关键参数率 0；其他目标在基线运行后确认。这些数值是项目建议，不是选题原始阈值。

## 8. 对比实验

固定测试集依次运行：

A. 仅稠密召回；B. 仅 BM25；C. 稠密 + BM25 + RRF；D. C + 重排序。

比较召回、回答质量、引用和耗时，证明混合检索及重排序的实际作用。分块大小、top-k、RRF k、阈值等每次只调整少数变量，并保存配置。

## 10. 发布前通过条件

- P0 功能端到端通过，无未解决的高风险数据错误和越权问题。
- 多文档人工评估完成，原始记录与配置可复查。
- 混合召回和重排序对比实验有结果，不仅展示最终回答。
- 无依据关键参数、伪造引用和跨会话泄露作为阻断问题处理。
- 已知限制（如扫描件、复杂表格）在交付说明中明确列出。
