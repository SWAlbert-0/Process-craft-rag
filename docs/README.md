# Process-craft-rag 开发前文档

## 1. 项目定位

本项目面向企业工艺知识场景，基于开源向量数据库与大模型 API，构建轻量级检索增强生成（RAG）系统。系统将 PDF 工艺文档解析、分块并向量化，通过稠密与稀疏混合召回、重排序和大模型生成，输出带引用来源的零件加工指令，并支持多轮对话。

本目录是正式编码前的统一依据。文档中的性能与质量数值若未注明来自选题，均为项目建议验收目标，需在基线测试后确认或调整。

## 3. 已确定的需求基线

1. 支持 PDF 工艺文档解析。
2. 支持文档分块、向量化及开源向量数据库存储。
3. 同时提供稠密语义召回与稀疏关键词召回。
4. 对混合召回结果重排序后再生成。
5. 支持多轮对话。
6. 回答和加工指令支持引用溯源。
7. 使用多份文档和人工评估测试回答准确性。

## 4. 默认技术边界

- 首个版本（MVP）面向单机或小团队内网使用，采用单租户、少量角色的轻量部署。
- 默认使用 FastAPI、Vue 3、Qdrant、SQLite、PyMuPDF，以及兼容 OpenAI Chat Completions 的大模型 API。
- 稀疏召回默认使用本地 BM25；向量模型和重排序模型可本地部署，也可替换为兼容 API。
- 原始文件默认保存在受控本地目录；不将公共云存储作为 MVP 的必要依赖。
- 系统输出仅作为工艺辅助建议，不直接下发机床或替代工艺人员审核。

## 5. 待项目启动时确认的事项

以下事项不阻碍文档设计和原型开发，但联调前必须形成明确结论：

- 模型服务商、具体模型名称、上下文长度、费用及数据合规要求。
- 样例 PDF 是否包含扫描件、复杂表格、图片和公式；扫描件 OCR 是否纳入本期。
- 加工指令的目标模板及必备字段，由工艺人员提供并确认。
- 用户规模和部署机器配置，以确定并发及模型运行方式。
- 人工评估集规模、评估人员和最终通过阈值。
