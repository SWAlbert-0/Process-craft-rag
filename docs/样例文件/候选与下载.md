## 6. 下载和入库约定

1. 下载到本目录内与内容对应的子目录；文件名使用英文小写和连字符，避免空格和特殊字符。
2. 下载中文件使用 `.part` 后缀，只有 `%PDF-` 文件头和打开校验通过后才改为 `.pdf`；失败时删除半成品。
3. 原始文件保持只读，解析文本、分块和索引写入项目数据目录，不覆盖样本原件。
4. 保存来源 URL、获取日期、许可、文件大小和 SHA-256；评估运行固定这些版本。
5. 公开可下载不等于允许再分发。CC 资料保留署名、许可链接和修改说明；`CC BY-NC` 不用于未经授权的商业场景。
6. 同一作品的 PDF 与 HTML 只选一个主版本，避免重复内容抬高召回。
7. HTML 采集限定域名和路径，遵守站点条款与访问频率，不无限制递归抓取。
8. 新工艺参数、安全要求和引用答案必须经人工复核；所有生成结果仍需工艺人员审核。

## 8. 中文开放工艺 RAG 数据集：判定标准与结论

本项目需要的直接工艺 RAG 数据集，理想上应同时包含：

1. 中文机械制造、加工工艺、设备、材料、检验或安全领域的原始文档。
2. 固定文档 ID 和可复现的内容版本。
3. 问题、参考答案、可接受答案变体及是否应拒答。
4. 对应原文证据，最好包含 PDF 页码或文本块 ID。
5. 明确的数据使用许可以及可实际获取的下载文件。

本轮检索到的资源中，**没有发现同时满足上述条件、可直接替换本项目自建数据集的公开中文工艺 PDF RAG 数据集**。最接近的是机械制造知识图谱问答和中文工厂结构化问答，但它们没有 PDF 页码，不能直接验证本项目的 PDF 解析和页级引用。

因此建议采用“现有英文 PDF 核心集 + 中文结构化专项实验 + 自建中文文档 RAG 题集”的组合，不把 KGQA、新闻 RAG 或预训练语料包装成中文工艺 PDF 数据集。

## 10. 中文重点候选详查

### 10.1 Mecha-QA：领域最匹配，但许可证缺失

**已确认内容**

- [数据集说明](https://github.com/reml-group/Mecha-QA/tree/main/dataset)明确以《机械制造手册》为知识源。
- 传统机械制造知识图谱 `kg.txt` 已下载，实际文件和论文均为 **1767 个三元组**；增材制造图谱 `kg_3d.txt` 为 838 个三元组。上游数据集 README 的“1761”与实际文件不一致，本地校验以实际文件为准。
- 问答总计 **1083 对**：传统机械制造训练集 571、测试集 142，增材制造测试集 370。
- JSONL 字段为 `问题`、`答案`、`实体`、`对应的三元组`。
- 实际读取的样例能够对应到材料牌号及答案三元组，不只是论文中的虚构示例。
- [论文](https://www.jos.org.cn/jos/article/html/7247)说明问答由 LLM 根据采样三元组生成，不是全部人工编写。

**与本项目的差距**

- 证据是知识三元组，不是原始 PDF 页文本；没有物理页码、原文片段或分块 ID。
- 原始专业书籍并未作为开放 PDF 随数据集发布，不能自行假定原书可再分发。
- 问答自动生成，需要抽查事实一致性、问题多样性和答案歧义。
- GitHub 仓库没有 LICENSE，公开可读不自动等于允许修改、再分发或商业使用。

**使用决策**

- 当前标记为 `kgqa_conditional`，不进入 `core_eval_v1`。
- 若获得作者明确许可，可将三元组赋予稳定 `triple_id`，开展中文术语、稠密/BM25、RRF 和相关性过滤专项实验。
- 引用只能标注“问题对应的知识三元组”，不得伪造 PDF 页码；结果与 PDF RAG 分开报告。

### 10.2 factory-ontology：许可清楚的中文结构化扩展

**已确认内容**

- 仓库及 [LICENSE](https://github.com/data3oil/factory-ontology/blob/main/LICENSE) 为 Apache-2.0。
- `data_valve/` 包含产品、批次、投料、原料、质检、设备、客户和销售 8 张合成数据表。
- `data_machining/` 和 `data_manufacturing/` 包含传动轴、齿轮、材料牌号、精度等级、设备等中文字段。
- README 描述 8 个库、331 道自动生成问答，其中 250 道可答、81 道无答案；证据来自 CSV 和本体关系。
- 还使用 UCI AI4I 预测性维护公开数据，UCI 数据仍需遵循其自身条款。

**与本项目的差距**

- 数据以 CSV 和图三元组为主，不处理非结构化 PDF 正文。
- 问题与答案由同一批结构化数据确定性生成，满分不能代表开放文档问答能力。

**使用决策**

- 制造相关子集已下载至 `05-结构化扩展验证/factory-ontology`，作为 `structured_ext` 验证中文结构化问答、拒答、证据返回和 GraphRAG 扩展。

- 如后续只选用阀门或机械加工合成表，应保留仓库版本、原始 CSV 哈希和合成数据说明。

## 11. 不应当作直接工艺 RAG 数据集的资源

- **通用新闻 RAG 基准**：可以测试中文检索框架，但不能证明工艺术语、参数或加工指令能力。
- **IndustryCorpus 等预训练语料**：文本规模不等于可评测性；没有固定工艺文档、期望答案和证据标注时，需要另行构建数据集。
- **UCI AI4I、CWRU 等传感器或故障数据**：适合预测性维护、分类或诊断，不是文本工艺知识库。
- **TechGPT、LevelField 等开放模型**：开放权重不代表训练图纸、工艺卡或问答数据同步开放，不把模型宣传中的训练规模当成可下载数据集。
- **论文中描述但未发布文件的数据**：只能作为联系作者的线索，不写成“已开源可下载”。
- **文档分享网站和来源不明题库**：许可与答案可靠性不明，不进入候选。

```text
├── questions.jsonl  # 问题、答案要点、拒答标记、证据页/块

```

每题至少保存：问题 ID、题型、原始问题、期望答案要点、关联文档、必须引用页、相关块（完成分块后补充）、是否应拒答、标注人和复核状态。模型可以辅助生成候选题，但关键工艺参数、引用和拒答标记必须人工复核。
