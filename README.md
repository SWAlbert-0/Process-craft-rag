# Process-craft-rag

基于检索增强生成（RAG）的轻量级企业工艺知识问答与加工指令生成系统。

项目利用开源向量数据库和大模型 API，对工艺 PDF 进行解析、分块、向量化存储和混合检索，生成带有文档名、页码及原文片段引用的零件加工指令草案，并支持多轮对话和效果评估。

## 项目目标

- 支持文本型 PDF 上传、解析、分块和版本化索引管理。
- 结合稠密语义召回与 BM25 稀疏召回，通过 RRF 融合和重排序提高检索质量。
- 基于实际检索证据生成普通问答和结构化加工指令草案。
- 支持多轮会话、引用溯源、证据不足拒答和历史引用快照。
- 使用多文档测试集、检索对比实验和人工评分验证系统效果。

## 当前阶段

项目按双周迭代推进，计划窗口为 **2026-11-09 至 2027 年 6 月**。第一次迭代为 **2026-11-09—11-22**，目标是使用真实文本型 PDF 跑通：

```text

→ 大模型生成 → 引用核查
```

## 默认技术方案

- 前端：Vue 3、TypeScript、Vite。
- 后端：Python、FastAPI、SQLAlchemy。
- 元数据与任务：SQLite、单后台 Worker。
- 检索：Qdrant、本地 BM25、RRF、可配置重排序模型。
- 文档处理：PyMuPDF，原始文件保存在受控本地目录。
- 生成模型：兼容 OpenAI Chat Completions 的大模型 API。
- 部署：开发环境支持本机运行，交付环境采用 Docker Compose。

具体依赖版本在工程初始化时锁定；模型名称、部署资源和最终性能目标以基线测试结果为准。

## 使用边界

系统输出为 **AI 辅助生成的工艺建议，必须由工艺人员审核**，不可直接用于生产控制或替代正式工艺规程。缺少材料、图纸、公差或设备条件时，系统应明确标记待确认信息，不得编造参数或引用。

外部样例资料仅在各自许可范围内使用。公开可下载不等于允许再分发，正式演示包须保留来源、许可和必要署名。
